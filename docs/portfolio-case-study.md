# CineMatch portfolio case study

## Problem

Movie discovery is a useful recommendation problem because one product must serve anonymous users,
people with only a few ratings, established users, and groups whose tastes differ. CineMatch aims
to show that progression in a reproducible local application without requiring a paid API.

## Scope and constraints

- FastAPI, React/Vite, SQLite, and Python 3.11.
- MovieLens latest-small by default; MovieLens 32M is opt-in.
- Popularity, content, explicit matrix-factorization, and hybrid strategies.
- Optional TMDB presentation enrichment with no core dependency on it.
- Local-first setup and a read-only public-demo posture.

## Approach

The system starts with a transparent popularity baseline, adds metadata similarity for item and
new-user discovery, then learns user/item embeddings from explicit ratings. A hybrid ranker can
blend available signals and fall back safely when a profile, item, or artifact is new. The API
separates model execution from the React experience, while SQLite keeps a demo inspectable and
portable.

Evaluation is designed as an offline, leakage-safe comparison rather than a single attractive
number. Rating error, top-K ranking quality, coverage, bias, latency, and fallback behavior answer
different questions and should be reported together.

## Results

The 2026-10-19 CPU run used MovieLens latest-small (100,836 ratings, 9,742 movies), seed 42,
and fingerprint `f99049f327bee630ea3d2a7e5be3ec494be7199977593032da402d18d266ee19`.
The protocol was a per-user chronological leave-last-two-out split with validation before test,
rating >= 4 as positive, full-catalogue candidates, and training-seen exclusions.

- Popularity: Recall@10 0.0523, Precision@10 0.0052, NDCG@10 0.0276.
- Content: Recall@10 0.0110, Precision@10 0.0011, NDCG@10 0.0067.
- Matrix factorization: Recall@10 0.0413, NDCG@10 0.0234, RMSE 0.9884, MAE 0.7643.
- Hybrid: Recall@10 0.0331, NDCG@10 0.0166 after validation-only weight selection.
- Warm single-user p95 ranking latency ranged from 0.99 ms (popularity) to 2.38 ms (hybrid).
- 363 users and 363 positive held-out interactions were evaluated.

Popularity is therefore the default for this version. The hybrid did **not** beat the baseline,
which is a useful finding rather than a result to hide. Full machine-readable metrics, coverage,
diversity, popularity bias, environment details, and the chart are regenerated by
`python -m scripts.cli evaluate`; they are ignored by Git because they are data-derived artifacts.
These offline results do not establish causal impact, engagement, or production-scale latency.

## What this demonstrates

- Translating a recommendation problem into baseline, personalized, and fallback paths.
- Designing an ML system around reproducibility and honest model limitations.
- Connecting offline artifacts to a typed API and interactive product experience.
- Recognizing data licensing, cold-start, operational, and hosting constraints.

## Next evidence to collect
